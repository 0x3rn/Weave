# Pre-push audit — 7 October 2026

Scope: member settings, notification delivery/history, login/sessions, admin authorization, Overview/Invites/Users, new admin operations, and the financial, storage, publishing, export, integration and maintenance boundaries those features use. Findings were reproduced with isolated PostgreSQL or mocked providers. This is a code and regression audit, not a guarantee that every possible defect has been eliminated.

## Fixed findings

| Finding                                                                                                                                         | Verified result                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Remember me only changed server lifetime; Firebase retained persistent browser authentication.                                                  | Login selects local or session persistence before authentication, including MFA. Checked cookies last 14 days; unchecked cookies have no persistent expiry and a one-day maximum server token lifetime.                                                                                  |
| Password/MFA updates silently enabled persistent sessions.                                                                                      | Refresh preserves the saved preference only for an owned device whose token fingerprint matches. Missing or mismatched bindings default to session persistence.                                                                                                                          |
| Login/logout return paths accepted URL normalization tricks.                                                                                    | Shared validation rejects external origins, backslashes and control characters.                                                                                                                                                                                                          |
| GET logout left the tracked session active; POST concealed revocation failures.                                                                 | Both revoke the device bound to the token fingerprint. Failures return 503 and retain cookies for retry. POST checks origin; GET rejects cross-site browser requests.                                                                                                                    |
| Account recovery did not check device revocation.                                                                                               | Recovery checks the owned device and token fingerprint, in addition to fresh identity confirmation.                                                                                                                                                                                      |
| Exchange evidence accepted unrelated conversation IDs.                                                                                          | A real exchange/dispute must exist; messages must be exchange conversations linked to that exchange. Downloads share the resource check. Policy, permission, reason and audit requirements remain enforced.                                                                              |
| Private verification statements and ledger notes reached read-only roles.                                                                       | Sensitive verification permission or ledger adjustment permission is required for those fields.                                                                                                                                                                                          |
| Author/assignment lookups exposed unrelated member emails.                                                                                      | Content lookups return eligible authors/staff without emails; assignment lookups return staff without emails.                                                                                                                                                                            |
| Billing accepted truthy confirmation strings, checked current instead of original payment currency, and prematurely completed provider changes. | Confirmation must be literal true; refunds match original currency; cancellation/reactivation remain submitted until provider confirmation.                                                                                                                                              |
| The existing Users adjustment bypassed the platform switch and amount limit.                                                                    | Approved migration 0015 enforces both checks after the idempotency check. Disabled and over-limit operations fail; previously completed operations still retry safely. Applied to the supplied database and both guards verified.                                                        |
| Production dependencies had published security advisories.                                                                                      | Next and its lint configuration remain on the patched 16.3 line. Nodemailer and compatible transitive dependencies are patched; gRPC/sharp overrides exclude vulnerable transitive versions. Production npm audit reports zero vulnerabilities.                                          |
| Shared SMTP transport could submit credentials and email without requiring encryption.                                                          | TLS and certificate validation are mandatory, timeouts are bounded, fallback credentials are removed, attachment file/URL access is disabled, and errors are redacted. Actual Nodemailer refuses plaintext before AUTH or message submission; missing configuration avoids a connection. |

The protected Overview, Invites and Users page/action source files remain unchanged. The Users database function change was approved and applied through migration 0015. The user subsequently authorized the shared SMTP fix, which is now applied. No approval remains pending for these findings.

## Accepted third-party development advisory

The full npm audit reports five high-severity entries from one unpatched `braces` advisory propagated through `micromatch`, `fast-glob`, the Next lint plugin and `eslint-config-next`. Deeply nested glob patterns can exhaust the parser stack. This is third-party development lint tooling, not Weave's application code; it is absent from the production dependency audit. The published advisory lists no patched version. On 7 October 2026 the user instructed that this third-party issue be left alone. The original lint dependency chain was retained, and an experimental replacement was removed in full. Check externally supplied lint/glob configuration before running it, and update the chain when an upstream fix is published.

Sources: [braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), [Next advisory](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), [Firebase persistence](https://firebase.google.com/docs/auth/web/auth-state-persistence), [Nodemailer TLS options](https://nodemailer.com/smtp).

## Verification

These regression tests use isolated PGlite and mocked providers without loading `.env.local`:

```powershell
npm run test:security
npm run test:email
npm run test:settings
npm run test:notifications
npm run test:admin
npm run test:admin-operations
npx tsc --noEmit
npm audit --omit=dev
```

- Security suite: 13 regression groups passed, including the existing Users adjustment policy, downloads audited before storage reads, role denials, persistence and revoked-session recovery.
- Admin operations: 17 groups passed, including database authorization, immutable audits, confirmations, idempotency, escrow conservation, contract/review requirements, policy enforcement, moderation, provider reconciliation and publishing.
- Overview/Invites/Users: 15 regression groups passed; protected source hashes match their baseline.
- Member settings and notification suites passed, including privacy/ownership, email retry, subscription verification/webhook signatures, account lifecycle, grouping and reminders.
- SMTP transport suite passed using actual Nodemailer against a local plaintext fixture plus mocked successful delivery. It checks TLS/certificate settings, both submission modes, timeouts, missing configuration, preserved delivery results and redacted provider errors. Invite, notification and settings suites passed again after the shared transport change. No external email was sent.
- Browser checks passed for actual login and admin components with mocked services: both checkbox states, persistence order, MFA, redirects, desktop/mobile layouts, keyboard dialogs, duplicate prevention, retry, reasons, settlement confirmation, support and publishing.
- TypeScript and lint checks for audit edits passed. Full source lint identified a forbidden `module` variable in the admin operations test loader; it was renamed and its suite passed again. Final source lint passed with zero errors and 332 existing warnings; generated audit artifacts and agent directories were excluded. Production build passed with dummy credentials and live services disabled. Existing Next middleware/Edge deprecation warnings remain.
- Read-only database checks confirmed migration 0014's 15 operational tables, ten checked functions and five checked guards, one active Super Admin, and no negative member/ledger balances. Approved migration 0015 was applied in a transaction and both adjustment guards were verified. Ledger and audit row counts were unchanged during application; no financial or maintenance operation ran against the supplied database during this audit.
- Secret scanning of the final 528 push-eligible files found no matches for supplied secret values or checked private-key/payment/GitHub/AWS patterns. The earlier scan of 780 unique blobs from the latest 12 unchanged commits also found no matches. `.env.local` and audit artifacts remain ignored. The scan does not cover every credential format or all historical commits.

Older exchange/messaging/storage scripts that load `.env.local` were not run against the supplied database because some create live fixtures or change storage. Isolated suites exercise related financial and message boundaries. Actual OAuth, SMTP delivery, Firebase sign-in/MFA enrollment, payment settlement, scheduled-job deployment and hosting configuration require provider/staging checks beyond this audit. No Git commit or push was performed.
